# 02 Codex 出图可行性验证

分支：`codex/codex-imagegen-spike`

## 目标

**先启动 ChatGPT 桌面应用随附的官方 Codex，复用用户已有的本机 ChatGPT 登录，直接把第 1 张原画按既有 G3 提示词重绘成 3D 风格，全程零次重新登录。** 先做独立实验。只有“复用了既有登录”和“交付了可核验的首图重绘”两项都通过，才进入扩展一键连接阶段。两个阶段都只支持 Codex。

**第一阶段实机结果（2026-11-21）：已有登录复用通过，首图重绘未通过。** 桌面端 Codex 0.171.0-alpha.13 在出图所用的权限下两次识别到已有 ChatGPT 登录。额外授权的首图提交 1 次，20.283 秒后报告只记录了文字，没有取得图片或保存路径。旧脚本未读取会话结束时的工具条目，无法据此确认真实调用次数。其余 4 张未测。本次出图授权已用完。

此前的临时登录试验另提交过首图 1 次，耗时 17.814 秒，产图 0 张。早期两次单图启动在握手前停止。调整官方程序维护运行文件的权限后，登录重连与零提交能力预检均通过。历次报告位置见实验 README。

## 第一阶段范围

**2026-11-21，零提交预检通过后，用户额外授权一次首图试验。** 用 `--first-image-once` 在同一台 Mac 上调用已验证的桌面端 Codex，沿用既有登录和原始 G3，最多提交第 1 张一次。普通额度、登录或其他前置条件无法确认即停。无论是否提交、成功、失败或中断，本次授权均不重试。结果写入 `output/codex-imagegen-2026-11-21-first-image-once/`，启动时以独占方式创建此目录，避免重复启动导致再次提交。

`--check-existing-login` 和 `--check-image-capability` 分别完成了实机登录重连和零提交出图预检。真实单图入口在两次连接及提交时使用同一套出图限制，允许签名程序维护启动所需的安装标识和启动器临时文件。工具直接返回的图片和本次临时目录内的图片可用于对照。若工具只返回外部路径或附件编号，则记录原因并停止。

独立实验沿用 `experiments/codex-imagegen/`，出图实验报告写入被忽略的 `output/codex-imagegen-<时间戳>/`，登录专用报告写入 `output/codex-existing-login-<时间戳>-<后缀>/results.json`。除本任务单和必要的输出忽略规则外，变更限于实验目录。本阶段不改扩展、服务或小助手。使用 Node.js 22，不新增 npm 依赖。确需依赖时先说明理由。

## 第一阶段接入与停止条件

1. 定位本机 ChatGPT 桌面应用随附的 Codex CLI，记录来源、可执行文件和实际版本。按应用包标识与元数据定位，避免写死包内路径。用 macOS 核对 OpenAI 签名后启动，预检、重连和首图固定使用同一个程序和同一份既有登录配置。定位失败、签名不通过或账号未确认时停止，不切换到 PATH 上的独立版。用该版本的 `codex app-server generate-json-schema --out <临时目录>` 或 `generate-ts` 核对协议。助手和实验脚本不得读取用户登录文件或其他私有配置，不读取、复制或记录令牌、API Key 或浏览器 Cookie，不设置 `ACCESS_TOKEN`。由官方 Codex 自行使用其管理的登录。
2. 实验脚本通过 `spawn('codex', ['app-server', ...])` 启动官方服务，以 stdio 传输换行分隔的 JSON-RPC。完成 `initialize`（`clientInfo: {name:"print-chamber-spike", title:"Print Chamber", version}`）→ `initialized` → `account/read`。返回的账号类型须为 `chatgpt`。关闭本次子进程，再用相同配置连接一次，两次都应直接识别已有登录。整个过程不创建登录配置、不替换日常 `CODEX_HOME`、不更改凭据存储方式，不调用登录命令、不打开授权页面。未登录、已过期或无法确认账号类型时，记录原因并停止。
3. 临时化的是每次任务新建的空工作目录和会话。模型任务只读、禁审批，关闭命令执行、网页搜索和 MCP。图片文件只允许写入本次临时目录，再由实验脚本保存报告副本。预检和真实首图使用相同的权限设置。应用包版本 0.171.0-alpha.13 曾在安装状态文件不可写时于握手前退出。若既有登录与当前写入限制不相容，或只能从禁止访问的目录取得结果，记录已证实的冲突及未知项，停止该路线。不得以放宽权限、临时登录、API Key 或桌面聊天代跑作为通过。
4. 提交图片前，检查 `image_generation` 已启用、供应商声明支持图片生成（本机协议为 `modelProvider/capabilities/read`）、所选模型支持图片输入，并读取可用的账号限额。供应商能力或登录状态无法确认、能力关闭、账号明确拒绝使用额度时，不提交原画。预检结果记为“可尝试首图”，实际出图能力以工具事件和图片为准。
5. 选择 `metrics.json` 中第 1 张原画，校验其 SHA-256。校验通过后，用 `thread/start` 建立临时只读会话，以本地图片输入项（`localImage`）和下述提示词发送一次 `turn/start`，监听至 `turn/completed`。不将图片 base64 塞进文本。校验失败或该张不可读时停止，不替换为第 2 张。

## 提示词

- G3 原文从 `output/scenes-g3-20261025-060950/prompt.txt` 读取，逐字使用，不修改。
- 外层指令只说明“调用图片生成工具，以附带图片为参考，按以下要求生成 1 张图，不要写代码、不要回复其他内容”，G3 文本原样拼接在后。外层指令写死在脚本中并原样记入报告。

## 测试样本

第一阶段只用 `output/scenes-g3-20261025-060950/metrics.json` 中 `sources[0]`（id 为 1）的原画，同目录的 `1-G3.png` 是这张图的本地 FLUX 对照。另外 4 张均标为未测。

## 运行方式与额度保护

以下是本次已执行的单图命令，包含两次连接及全部预检。本次授权已结束。

```sh
node experiments/codex-imagegen/run.cjs --first-image-once
```

- 默认无参只做预检。旧 `--limit 1` 已达到两次开发上限。本次追加授权仅对应上述一次性命令。`--login-check` 和 `--login-first-image` 属于历史临时登录实验。本阶段不使用临时登录或全组命令。
- 单张超时 5 分钟，超时记为失败，按协议中断并回收本次进程。若开发沙箱禁止启动官方服务或联网，只完成允许的离线检查，说明阻碍并给出用户在普通终端用现有登录验证的最短命令。不得要求用户以重新登录来排错。
- 若 schema 提供账号限额读取，在首图提交前后各读取一次，区分不可观测、读数未变化和额度耗尽。

## 记录与报告

每张图记录：开始/结束时间、总耗时、首个事件延迟、`turn/completed` 状态、是否真的调用了图片生成（依据事件中的 item 类型而非模型文字）、输出图片路径与尺寸、Codex 文字回复（截断 500 字）、限额前后值、错误信息。

产出：

- `output/codex-imagegen-<时间戳>/results.json`：上述原始记录、运行环境（Codex 版本、外层指令、G3 SHA-256），以及本次是否沿用日常登录、两次连接的账号类型和预检结果。只记录验证所需的状态。
- `output/codex-imagegen-<时间戳>/comparison.html`：每行“原画 | 本地 FLUX G3 | Codex”三列并排，下方列出耗时与状态。图片用相对路径引用复制到该目录的文件。
- `experiments/codex-imagegen/README.md`：如何运行、协议要点（实际用到的方法名与事件名）、已知限制。

## 必须回答的问题（写在回复与 results.json 的 `findings` 中）

1. Codex 能否以附带原画为参考出图（图生图），还是只能文生图？
2. 首图实际提交几次、产图几张？其余 4 张标为未测。5 张未全部实际提交前，全组成功率填“未验证”。
3. 首图的提交至终态耗时是多少？若取得图片，注明成功样本数后给出中位数与最大值。失败耗时单列。
4. 额度消耗是否可观测？本次首图尝试的前后读数变化是多少？
5. 输出图片的格式、尺寸及文件位置（是否由 Codex 写到临时目录之外，例如 `~/.codex` 下）。
6. 未登录、额度用尽、`image_generation` 关闭时分别返回什么错误？可用模拟响应验证错误处理。请保留日常账号与配置，真实返回未观察到时写“未验证”。
7. 本机检测 Codex 可用性的最小可靠步骤（命令与判断条件），供后续自动扫描使用。

## 第一阶段验收标准

1. **既有登录可复用。** 在与首图一致的启动和权限设置下，零出图预检完成握手。断开再连仍识别为 ChatGPT 登录，全程无新登录。退出后本次启动的进程无残留，保留其他正常使用的 Codex 进程。
2. **确实重绘了第 1 张。** 记录一次实际提交、对应会话中完成的 `imageGeneration` 工具事件、可解码的输出图片及其格式和尺寸。`comparison.html` 能并排显示第 1 张原画、`1-G3.png` 和 Codex 结果。若事件提供输入 SHA-256，必须与原画匹配。若该版本未提供，记录所附原画的哈希，结合对比图人工核对主体和构图，标明证据来源。哈希不符或参考关系无法确认时，该项不通过。仅有模型文字、工具开关或 `turn/completed` 均不算产图。
3. **失败也要可判读。** `results.json` 与对比页区分“未提交”“已提交但没有工具调用”“工具已调用但未取得有效图片”“已取得首图”。回答上述 7 问，未验证的项说明原因。成功交付报告本身不足以进入第二阶段。
4. **遵守范围与限额。** 检查分支差异仅含本任务单、实验目录与可能的 `.gitignore`。审核实验代码没有读取用户凭据或处理令牌的逻辑。运行 `grep -rn "auth.json\|ACCESS_TOKEN\|\.codex/" experiments/`，匹配只应出现在禁止说明或注释里。开发阶段不跑全组，不自动重试，不触碰另外 4 张原画的生成额度。

本轮逐项核对：

1. **通过。** 首次与重连均为 `chatgpt`。脚本在两次连接结束时分别等到子进程退出；报告记录的出图服务进程已退出。
2. **未通过。** 首图实际提交 1 次，旧脚本观测到的图片工具事件 0 次，产图 0 张。具体原因未知。
3. **通过。** JSON 报告包含 7 项结果；对比页显示原画及 FLUX 对照，并将 Codex 结果标为“已提交，未观测到图片工具调用”。
4. **通过。** 本次额外授权只用于第 1 张一次。分支差异限于本任务单与实验目录，原画与运行报告保留在本地。

后续离线验证中，分别关闭、开启 `code_mode`，两次本机模拟服务收到的首个文字请求均未显式声明图片工具。此对照未使用真实账号或图片。现有脚本已修复结束条目的漏记，成功、失败、重复与不完整条目均用模拟消息验证。完整结果见实验 README。

## 第二阶段（首图验收通过后接入扩展）

第一阶段第 1、2 项均有真实证据且满足其余约束后，才开始此阶段。此前仅记录方案，不开发扩展连接功能。

- 首次安装时登记 Chrome Native Messaging 本机助手，白名单只允许 Print Chamber 的扩展 ID。扩展后台通过 `chrome.runtime.connectNative()` 按需启动助手。助手沿用第一阶段验过的桌面端随附 Codex，直连官方 `codex app-server`。只发现和连接 Codex，不扫描或启动 Claude Code，不引入 ACP 多 Agent 适配层。
- 用户在现有扩展界面点一次“连接本机 Codex”，助手以第一阶段验过的方式读取账号状态，成功后显示“已连接”。连接按钮提交 0 张。断开重连仍复用已有有效登录。账号不可用时显示原因，不自动发起登录。
- 用户明确点击现有生成操作时才提交原画。验收要求图片通过这条实际连接返回，并在现有界面显示。未产生图片时显示对应状态，不自动重试。不另做演示页面。
